Model Stock & Flow Persediaan

Model sistem dinamik dengan satu stock (stok persediaan), dua flow (barang masuk dan penjualan), dan beberapa variabel bantu. Langkah waktu: 1 hari.

Diagram

Garis tebal = aliran barang (flow). Garis putus-putus = informasi yang memengaruhi flow. Umpan balik: posisi persediaan menentukan kapan pesanan dibuat.

Persamaan model

  1. Stok(t+1) = Stok(t) + Barang_Masuk(t) − Penjualan(t)
  2. Permintaan(t) = Permintaan_Data(t) × (1 + Perubahan%), dibulatkan ke unit
  3. Penjualan(t) = min(Permintaan(t), Stok(t) + Barang_Masuk(t)). Selisihnya adalah permintaan tak terpenuhi.
  4. Posisi(t) = Stok(t) + pesanan yang belum tiba
  5. s = μ·L + z·σ·√L dan S = s + μ·H
  6. Jika Posisi(t) ≤ s, pesan S − Posisi(t) unit; tiba pada hari t + L

μ dan σ adalah rata-rata dan simpangan baku penjualan harian, z diturunkan dari tingkat layanan, L = lead time, H = cakupan pesanan (hari).

Tiga mode barang masuk

Kebijakan pemesanan (default)
Barang masuk dihasilkan oleh aturan (s, S) di atas. Pesanan otomatis menyesuaikan konsumsi.
Historis dari data
Memakai Units Ordered pada data asli sebagai pesanan harian, tiba setelah lead time.{% if not meta.has_orders %} Tidak tersedia pada dataset yang sedang dipakai.{% endif %}
Manual
Jumlah tetap per hari yang Anda input, tiba pada hari yang sama tanpa lead time.

Asumsi stok dan pengadaan

Stok dan permintaan

  • Permintaan = penjualan harian pada data ({{ 'Units Sold' if meta.has_orders else 'sales' }}), dijumlahkan untuk toko dan barang yang dipilih. Data tidak mencatat penjualan yang gagal karena stok habis, jadi penjualan dianggap sama dengan permintaan.
  • Stok awal {% if meta.has_inventory %}diambil dari Inventory Level aktual pada tanggal mulai simulasi (dijumlahkan), kecuali Anda mengisinya sendiri.{% else %}tidak ada pada dataset, sehingga diasumsikan sebesar level S, kecuali Anda mengisinya sendiri.{% endif %}

  • Stok pada data tidak dipakai sebagai neraca. Inventory Level pada hari berikutnya tidak mengikuti rumus stok sebelumnya + pesanan − penjualan, dan{% if meta.order_to_sales_pct %} total Units Ordered hanya sekitar {{ meta.order_to_sales_pct }}% dari total Units Sold{% endif %}. Karena itu stok dihitung ulang oleh model, bukan disalin dari data.
    • {% endif %}
  • Lost sales: permintaan yang tidak terpenuhi hilang, tidak ditunda (tanpa backorder). Stok tidak pernah negatif.
  • Skenario +20% dan +50% mengalikan permintaan setiap hari. Pola naik-turun harian tetap berasal dari data asli.

Pengadaan

  • Lead time 2 hari sebagai nilai awal. Dataset tidak mencatat waktu pengiriman, jadi ini asumsi yang dapat Anda ubah.
  • Tinjauan harian: posisi persediaan diperiksa setiap akhir hari.
  • Tingkat layanan 95% (z ≈ 1,645) dan cakupan pesanan 3 hari sebagai nilai awal; keduanya dapat diubah.
  • μ dan σ dihitung dari penjualan sebelum periode simulasi, supaya model tidak memakai data masa depan.
  • Pesanan di jalan pada hari pertama: sebesar μ per hari (kondisi tunak), kecuali mode historis yang memakai pesanan nyata.
  • Parameter s dan S dikunci pada kondisi baseline sehingga dampak lonjakan permintaan terlihat. Opsi "pengadaan adaptif" menghitung ulang s dan S untuk tiap skenario.
  • Tidak dimodelkan: kapasitas gudang, biaya, kerusakan, jumlah pesanan minimum.
